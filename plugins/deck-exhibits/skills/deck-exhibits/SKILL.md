# Экспонаты для слайдов

Скилл отвечает на три вопроса: какой приём подачи взять под сообщение слайда, как нарисовать его так, чтобы палитра, шрифт и тексты были правильными без ручной вычитки, и как собрать слайды в деку с источниками, номерами и PDF.

**Папка скилла.** Ниже `SKILL_DIR` это `${CLAUDE_SKILL_DIR}`. Если переменная не подставилась (Codex, скилл из claude.ai), `SKILL_DIR` это папка, где лежит этот SKILL.md. В коде агента: `SKILL_DIR = '<эта папка>'`.

Состав:
- `INDEX.md`: выбор приёма в два шага. Читать на каждый слайд с экспонатом.
- `cards/<приём>.md`: рецепт: вход, параметры, правила, пример вызова, описание публичных образцов со ссылками.
- `exhibits/`: функции, по одной на приём. Цвета и шрифт только из темы.
- `themes/v3_golos.toml`: тема по умолчанию (Golos Text, один синий акцент, остальное серое). Единственное место, где живут цвета, шрифт и кегли.
- `frame/deck.py`: рамка деки (заголовок, экспонат, сноски, источники, номер, PDF). Образец `frame/example.py`.
- `align/`: выравнивание краёв в деке и проверка готовой деки.
- `catalog.py`: реестр приёмов, из него `build_docs.py` собирает INDEX и карточки.

## Профиль пользователя (личные настройки скилла)

Перед первым слайдом ищи профиль того, кто поставил скилл. Берётся первый найденный:

1. `.agents/deck-exhibits/profile.md` в корне текущего проекта;
2. `~/.agents/deck-exhibits/profile.md`;
3. `.claude/deck-exhibits/profile.md` в корне текущего проекта;
4. `~/.claude/deck-exhibits/profile.md`.

Первые два пути для Codex, последние два для Claude Code.

Профиль может быть папкой: `profile.md` в ней точка входа, рядом файлы, на которые он ссылается (стиль, правила по клиентам, свои образцы, тесты). Читай `profile.md` целиком, а соседние файлы тогда, когда `profile.md` велит их читать.

**Профиль есть.** Он дополняет этот текст: своя тема и шрифт, кто принимает строку «Экспонат» в ТЗ, своя сборка деки вместо `frame/`, соседние скиллы, свод замечаний к декам, свои отклонённые приёмы, папка своих образцов. Где профиль и этот текст расходятся, прав профиль. Два правила профиль не отменяет: предупреждения не глушить, кадр смотреть глазами.

**Профиля нет.** Работай на штатном: тема по умолчанию, рамка `frame/deck.py`, строку «Экспонат» показывай пользователю до вёрстки. В конце первого отчёта одной строкой предложи завести профиль по шаблону [reference/profile-template.md](reference/profile-template.md). Предлагать один раз за разговор.

## Главный принцип: понятно без чтения

Слайд должен считываться за несколько секунд, не читая текст. Поэтому перед любым текстовым приёмом (таблица, этапы, пункты, столпы, рамка) проверь: есть ли в содержании числа сравнения, было и стало, доли, кратность, сроки. Есть: главные из них идут графиком (`pair_delta` для было → стало, `columns` для ряда, `bar_ranked` для рейтинга), текст остаётся для смысла. Код это проверяет: три и больше чисел с единицами в тексте текстового приёма дают предупреждение «цифры утонули в тексте».

Дерево метрики и матрицу инициатив рисовать (`driver_tree`, `matrix_2x2`), а не перечислять текстом. Две таблицы рядом, таблица на весь слайд с одними словами, текст в ячейках вместо картинки процесса: сначала спроси, какая логика у слайда (вход → процесс → результат, сначала → потом, было → стало), и возьми приём под неё.

## Порядок на каждый слайд

1. **Сообщение.** Возьми заголовок-вывод слайда и найди тип сообщения в таблице 1 `INDEX.md`.
2. **Форма данных.** Сравни кандидатов по таблице 2: сигналы в ТЗ, «не брать, если», потолки. Сколько объектов, есть ли время, складываются ли части в целое, есть ли отрицательные, одна единица или разные.
3. **Запиши в ТЗ слайда** строку: `Экспонат: waterfall (highlight «Цены»), почему: заголовок про вклад факторов в разницу двух чисел, шагов 5`. Пользователь видит её до вёрстки и может поправить.
4. **Открой карточку** приёма и собери вызов по примеру из неё.
5. **Нарисуй и проверь.** `ex.warnings` должен быть пустым. Предупреждения не глушить.
6. **Собери деку** рамкой (раздел ниже) или вставь `ex.svg` в свою: ширина рисунка 1168 px при масштабе 1:1 со слайдом 1280×720.
7. **Посмотри кадры глазами** (`<дека>_кадры/sNN.png`) и прогони проверку краёв.

Когда ни один приём не ложится: предложи пользователю 2–3 варианта словами или наброском, выбранный пишется функцией (раздел «Новый приём»).

## Вызов

```python
import sys; sys.path.insert(0, SKILL_DIR)
import exhibits as X
ex = X.waterfall(('Маржа 2025', 18.4), [('Цены', 2.1), ('Объём', 1.3), ('Себестоимость', -0.9)],
                 ('Маржа 2026', 20.9), unit='п.п.', decimals=1, highlight=['Цены'])
assert not ex.warnings, ex.warnings
```

Общие параметры у всех функций: `theme=X.load_theme(путь)` (по умолчанию v3), `mode='показ'|'чтение'` (шкала кеглей), `width` (по умолчанию ширина из темы). Графики в ряд: только `X.panels([lambda **kw: X.columns(..., title=, sub=, **kw), ...])`, тогда оси и верх у панелей общие. Таблицы и схемы в ряд: `X.hstack([a, b])`, каждый строить с `width=(1168 - 40) / 2`. Сеткой HTML рисунки рядом не ставить: оси разъезжаются.

## Дека: рамка в одну команду

```python
import sys; sys.path.insert(0, SKILL_DIR + '/frame')
from deck import Deck, X
d = Deck('Материал к встрече')
d.title('Главная мысль материала', 'Для кого и когда')                    # на титуле номера нет
t = 'Рост замедлился с 26 до 17,7%[1], и нужна новая выручка'
d.slide(t, X.pair_delta([...], height=d.room(t, sources=[1]) - 110),
        sources=[('Рейтинг TAdviser, 2026', 'https://...')])
d.build('материал/слайды/дека.html')   # HTML, PDF по слайду на страницу, кадры PNG, отчёт проверки краёв
```

- Сноска `[1]` в заголовке или в `lead` становится надстрочной цифрой; у неё должен быть источник с тем же номером, иначе сборка падает.
- Гипотеза подписывается в заголовке: «Гипотеза: …».
- `d.room(заголовок, lead, sources)` даёт высоту, которая осталась экспонату: передай её в `height` или `max_h` приёма, иначе низ слайда пустой. Экспонат выше места рамка называет в предупреждении.
- Целый образец: `python3 SKILL_DIR/frame/example.py` (пишет `пример_деки/` в текущую папку).
- Только HTML и PDF. PPTX скилл не собирает.

## Что гарантирует код, а что остаётся за тобой

Код гарантирует:
- **Палитру.** Цвета задаются ролями (`accent`, `grey`, `bad`). Роль, которой нет в теме, роняет сборку. Литерал цвета в функцию не передаётся.
- **Шрифт и кегли.** Golos Text из темы, кегль из шкалы режима, ниже `min` уходит предупреждение.
- **Перенос текста.** Ширина меряется по файлу шрифта. Предлоги, союзы и числа с единицами не отрываются от следующего слова. Если текст не влез, сборка падает с `FitError` и подсказкой, до скольких знаков сократить.
- **Числа по-русски.** `X.num`: запятая в дробях, узкий пробел в тысячах, настоящий минус, половины округляются вверх.
- **Сходимость.** Мост проверяет сумму шагов, серии проверяются на длину, потолки приёма проверяются (`DataError`).
- **Раскладку.** Подписи у данных, легенды только там, где без них никак. Наезды подписей и выход за край ловятся в `warnings`. Подпись точки матрицы ищет место в своей клетке, а если перешла в соседнюю, это предупреждение.
- **Различимые классы.** Два класса (или класс и узлы без класса) почти одного цвета, ΔE меньше 8, дают предупреждение (`driver_tree`, `matrix_2x2`).
- **Единицу разницы процентов.** У `pair_delta` при `sub`, который кончается на «%», разница подписывается «п.п.» сама.

За тобой:
- выбор приёма и строка «почему» в ТЗ;
- что выделить акцентом: только то, о чём заголовок (`highlight`);
- заголовок-вывод (без подписи над ним), источник и номер слайда: в рамке это делает `Deck`, в своей деке ты;
- своя подпись разницы, когда арифметика не говорит главного (`delta='в 120 раз'`);
- сверка заголовка с рисунком: «три инициативы» в заголовке значит три точки в клетке, а не четыре;
- тексты подписей на связность: подпись колонки или строки вместе с ячейкой читается одной фразой, без обрывков; если есть скилл вычитки русского текста, прогнать подписи через него;
- кадр глазами перед отдачей.

## Ошибки

- `FitError`: сократи текст или возьми приём просторнее. Мельчить кегль и резать текст нельзя.
- `DataError`: данные не той формы для приёма. Сообщение называет, какой приём взять вместо.
- `KeyError` про иконку: имя иконки Lucide. Ошибка подсказывает похожие имена, полный список в `icons/lucide-sprite.svg`.
- `DeckError`: сноска без источника.
- «не найден Chrome»: установить Chrome, Chromium или Edge либо задать путь в переменной окружения `CHROME`. HTML деки пишется и без браузера.
- `ModuleNotFoundError: tomllib`: Python старше 3.11, поставить новый.

## Тема под клиента

Скопировать `themes/v3_golos.toml` в папку деки, поменять значения, роли не трогать: `X.load_theme('/путь/тема.toml')` и `Deck(..., theme='/путь/тема.toml')`. Шрифт клиента: положить файл TTF и указать в `[font] file`, иначе перенос будет мериться по чужим ширинам. Цвета клиента ставятся в роли `accent`, `accent_dark`, шкалу `accent_*` и `surface`. Семантика `good` и `bad` остаётся для плашек разницы.

## Новый приём

Потолки приёма бывают двух видов, и у каждого в `catalog.py` должно быть видно, откуда он: правило восприятия из исследований (процесс 4–5 шагов) или техника раскладки. Техническое ограничение не записывать числом: его проверяет код по месту (`FitError` по высоте, ширине, строкам). Иначе агенты примут раскладку за правило и откажут подходящему приёму.

1. Функция в подходящем файле `exhibits/` (рисует только через `Fig`, роли цветов, `f.para` и `f.rich` для текста, `need` для потолков).
2. Демо в `tests/demo.py` на правдоподобных данных.
3. Запись в `catalog.py`: сообщение, сигналы, «не брать, если», потолки, правила, образцы.
4. `python3 tests/demo.py <демо>`, кадр глазами, `warnings` пустые.
5. `python3 build_docs.py --no-html` пересоберёт INDEX и карточки (`--shots` ещё и кадры демо в `_preview/`).

## Выравнивание и проверка краёв

Папка `align/`. Работает с любой HTML-декой, где слайды это `.slide`, а ряды блоков это сетки `.g2,.g2w,.g3,.g4` (переопределяется). Рамка `frame/deck.py` подключает всё сама.

- `align/align.js` встраивается в деку последним скриптом. После загрузки шрифтов доводит низы соседних блоков одного ряда, если разница не больше 22% высоты ряда. Большую разницу не трогает. Настройка: `window.DECK_ALIGN = {slide, rows, fig, max}`.
- `python3 SKILL_DIR/align/check.py <дека.html>` проверяет служебное на слайдах (пути, .md, «сверить с», «со слов», «канон», номера реестра), ошибки текста (длинное тире, точка с запятой, обращение на «ты», двоеточие в заголовке, кроме «Гипотеза: …») и четыре края: низ, верх, право и лево. Ещё строка «перелив»: содержимое слайда заходит под строку источников (`.src`) или за низ слайда. Отчёт «края ровные, кухни и ошибок текста нет» значит можно показывать. Ключ `--no-text` для внутренней деки.

## Проверки

- `python3 SKILL_DIR/tests/demo.py` рисует все приёмы и печатает предупреждения. Перед изменением ядра и после него прогон должен быть чистым.
- `tests/routing_cases.md`: ТЗ слайдов с правильным приёмом. Проверка выбора: отдать агенту только `INDEX.md` и ТЗ и посчитать совпадения.
